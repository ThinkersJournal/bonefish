# Bonefish roadmap

Order matters: survey, then design, then code. Every code row ships with a negative control (a test that fails when the behaviour is removed). Statuses: todo, doing, review (PR open), done.

| Row | What | Status |
|-----|------|--------|
| R0 | `ROADMAP.md`, CI (fmt, clippy, test, doc, cargo-deny, portfolio), then branch protection requiring them (PM) | done |
| R1 | Survey and design note `docs/SURVEY.md`: options first, recommendation, no code. Covers the oneMKL SYCL interface (`oneapi::mkl::blas`, `dft`), the C++ shim shape, Level Zero, Linux and Windows builds, and what a parser and emitter for SYCL/DPC++ kernels owes Unpopped's contract | done |
| R2 | `bonefish-sys`: `extern "C"` shim over oneMKL SYCL built with `icpx -fsycl`, no `onemkl-sys` dependency (PM ruling 2026-10-30). Done: queue, USM, blas gemm, level-1 (axpy scal copy swap dot nrm2 asum iamax) and gemv (s, d), complex DFT. Measured on CPU/OpenCL devices only (Windows laptop, Linux CI); GPU UNVERIFIED. Left: rest of blas (level 2/3 beyond gemv/gemm, batched, half/bf16/complex), real-domain DFT, GPU runs once hardware is available | review |
| R3 | `bonefish`: safe API over the shim. Done: `Queue`, `UsmBuffer<T>`, `blas::gemm`, `Dft` (c2c), Rust-side bounds checks, compiles without oneAPI (`Error::Unavailable`). CPU/OpenCL device only; GPU UNVERIFIED | review |
| R3b | Safe layer follow-ups: level-1/`gemv` wrappers; `Event` and dependency lists (needs non-blocking shim calls first); `Send`/`Sync` for `Queue` once `sycl::queue` thread-safety is verified from the SYCL spec; real-domain DFT | todo |

Done: contiguous elementwise f32/f64 + oracle-checked tests on the CPU/OpenCL device. Open with Unpopped: launch-ABI field, `ArtifactKind` for SYCL, a `sycl:` TargetId (via KISS). Left: more schedules and dtypes, GPU runs | review |
| R4b | SYCL/DPC++ parser (tree-sitter C++, restricted-idiom recogniser) on Unpopped's parse contract | todo |
| R5 | Intel GPU backend design with the Fuel lane (Fuel ROADMAP row 127: A770, Vulkan vs oneMKL via SYCL) | todo |
| R6 | Take over the `onemkl` / `onemkl-sys` ROADMAP, starting with PR #1 in `ciresnave/onemkl` (pending CireSnave's decision) | blocked |
| R7 | **icpx default fast-math vs accuracy claims.** Measured (icpx 2026.1.0.20260617, Windows, CPU/OpenCL device, JIT; one kernel `out = expf(x)` at x = 3.0f, correct value 20.08553695678711): default flags give 20.08906364440918 (rel error 1.8e-4); `-ffp-model=precise` and `-fno-fast-math` each give 20.085536956787109; `-fsycl-fp32-prec-sqrt` changes nothing; `#pragma float_control` is ignored on this target; `sycl::exp(x)` is correct under the default flags. Any accuracy or perf claim for Intel (Fuel included) must state the flags and the math spelling: libm names (`expf`) under default flags are NOT comparable with CUDA or Vulkan results. `bonefish-sycl-emit` avoids it in source (every libm call becomes `sycl::`); a user compiling their own SYCL needs `-ffp-model=precise` (or `-fno-fast-math`). Not yet measured: other functions (only `exp` was run), Linux, any GPU (GPU math lowering may differ), `-fp-model=` spellings other than the two above. Left: sweep every unary op default-vs-precise vs `sycl::`, then repeat on a GPU | todo |
